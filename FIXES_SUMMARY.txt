📌 问题 1: Debian 12 / Ubuntu 24.04 niri 编译失败
─────────────────────────────────────────────────────────────────────────────
原因
  • 包名版本差异（libdisplay-info-dev vs libdisplay-info0-dev）
  • 构建依赖验证不足，导致隐蔽的链接错误
  • cargo 日志输出不详细，无法诊断

修复方案 ✅
  ✓ 增加 DEB_NIRI_BDEPS_MAP 包名映射表（自动转换 Debian 12 包名）
  ✓ 强化关键依赖硬验证（build-essential, clang, libwayland-dev）
  ✓ 添加 RUST_LOG=info cargo build --release -vv（详细日志）
  ✓ 失败时给出清晰的包名提示，建议升级系统版本

修改位置
  • 第 1112-1116 行：DEB_NIRI_BDEPS_MAP 定义
  • 第 1330-1355 行：Debian 依赖安装与验证逻辑
  • 第 1347 行：cargo 构建命令增加 -vv 和 RUST_LOG

1️⃣  niri 编译仍然失败
   查看详细日志：
   $ tail -100 ~/.local/state/eilNiri/niri-build.log

   检查关键依赖：
   $ dpkg -l | grep -E "build-essential|clang|libwayland-dev"

   手动安装缺失的包：
   $ sudo apt-get install build-essential clang libwayland-dev wayland-protocols

2️⃣  系统组件未被禁用
   查看禁用清单：
   $ cat .system_disabled

   检查禁用状态：
   $ systemctl --user list-unit-files | grep masked
   $ ls ~/.config/autostart/

   强制重新禁用：
   $ rm .replicate_progress
   $ sudo ./install.sh restore

3️⃣  下载超时
   使用 GitHub 镜像：
   $ EILNIRI_GH_PROXY="https://ghfast.top/ https://mirror.ghproxy.com/" \
     sudo ./install.sh restore
