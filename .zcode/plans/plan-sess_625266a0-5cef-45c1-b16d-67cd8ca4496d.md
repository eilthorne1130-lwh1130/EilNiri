# RHEL-install.sh 源码编译链修复（针对测试机 EL10 报错）

## 诊断结论（已查证）

测试机表现为 EL10 特征，且**上一轮 COPR 修复已生效**（niri 在 EL10 上只能来自 `yalter/niri` COPR，安装成功）。截图三个清单的真实含义：

- **"Failed 6 + Manual 8" = 真实失败**；**"Selected packages failed to install (21)" 大部分是审计误报**（stage_verify 用 `rpm -q` 检查，看不到源码/zip/别名方式安装成功的包：mako/grim/slurp/hyprlock 源码编译成功、字体走 zip、polkit-agent 是逻辑别名而非真包名）。
- **失败的 dnf 包全部是 EPEL10 确实没有的**（已在 packages.fedoraproject.org 逐一查证：waybar、mako、fuzzel、grim、fcitx5 全家、mate-polkit 均无 EPEL10 构建）——dnf 失败本身是 EL10 生态现实，问题在于**源码编译兜底链自身有缺陷**，全部倒在半路：
  1. `RHEL_SOURCE_BUILD_DEPS` 是通用清单，缺 waybar（gtkmm/gtk-layer-shell/jsoncpp/spdlog/fmt/libnl3/libmpdclient 等）、copyq（qt6 系列）、playerctl（gobject-introspection）的真实依赖 → 编译在依赖检查/构建时失败
  2. `git_clone_gh` 不拉子模块 → fuzzel 的 fcft/tllist（git submodule）必失败
  3. `build_source_project` 只支持 cmake/meson → brightnessctl（纯 Makefile 项目）必失败
  4. hypridle 的 `cmake ... pkg_check_modules` 报错 = 缺 -devel 模块（依赖表遗漏；hyprlock 能过说明 hypr C++ 栈编译链基本可用）
  5. zoxide 无 EL10 包，脚本只报 MANUAL 没有兜底
- fcitx5 全家在 EL10 无包、无 COPR（已搜索确认无 epel-10 chroot 的 fcitx5 COPR）、无源码兜底 → 目前只留 FAILED 无指引
- power-profiles-daemon 在 EL10 AppStream 理应存在却三连失败 → 原因待日志定位
- CRB/EPEL 状态未知（mako/hyprlock 能源码编译说明部分 -devel 可用；你稍后贴 `dnf repolist` 确认）

## 修复清单（全部改动限于 RHEL-install.sh + README）

1. **按项目拆分源码构建依赖表**：新增 `SRC_DEPS_WAYBAR`（gtkmm30-devel/gtkmm4.0-devel、gtk-layer-shell-devel、jsoncpp-devel、spdlog-devel、fmt-devel、libnl3-devel、libmpdclient-devel、libevdev-devel、pulseaudio-libs-devel、systemd-devel 等）、`SRC_DEPS_COPYQ`（qt6-qtbase-devel/qt6-qtdeclarative-devel/qt6-qtsvg-devel/qt6-qttools-devel 等）、`SRC_DEPS_PLAYERCTL`（glib2-devel、gobject-introspection-devel），`install_source_package` 按包名叠加安装（tolerant，缺名不阻塞）。
2. **git_clone_gh 支持子模块**：clone 成功后执行 `git submodule update --init --recursive`（失败仅警告，不中断）——修复 fuzzel。
3. **build_source_project 增加 Makefile 分支**（`make -j$(nproc)` + `make install PREFIX=/usr`）——修复 brightnessctl。
4. **源码构建失败时 MANUAL 附带缺失依赖清单**（BDEPS_MISSING）+ "需 CRB/EPEL" 提示，不再只给日志路径。
5. **zoxide 加 cargo 兜底**（install_zsh_extras 内，ensure_rust 后 `cargo install zoxide`）。
6. **fcitx5 全家在非 Fedora 上转明确 MANUAL 指引**（"EL10 无 fcitx5 RPM，输入法可选：改用 ibus / 源码编译 / 换 Fedora"），不再反复 dnf 重试后只留一条干巴巴的 FAILED；Fedora 路径保持不变。
7. **stage_verify 审计修正**：polkit-agent 用 `resolve_rhel_package` 解析出的真名检查；SOURCE_PKGS 家族（waybar/mako/fuzzel/copyq/grim/slurp/playerctl/brightnessctl/hyprlock/hypridle）改用 `command -v` 检查；nerd 字体用 `fc-list` 检查——消除误报，让审计可信。
8. **ensure_rhel_repos 强化**：EPEL 启用失败时尝试从阿里云/USTC 镜像 URL 直装 epel-release RPM 回退；CRB 不可用时写入显著 warn + MANUAL 提示（-devel 缺失会影响全部源码构建）。
9. **FAILED_PKGS 条目附带错误细节**：dnf 失败时 tail 一行 dnf-errors.log 进条目，方便远程定位（也覆盖 power-profiles-daemon 的未知失败）。
10. **实施时顺手探测**：用 COPR 全文搜索找带 epel-10 chroot 的 waybar COPR（fcitx5 已确认没有），找到则按现有"HTTP 探测 + 显式 chroot"机制接入 `RHEL_COPR_PKG`，找不到不动。
11. **README 已知限制**补充：EL10 上 fcitx5 不可用的说明、源码构建对 CRB/EPEL 的依赖。

## 验证方式

- `bash -n` + 全量 diff 走查（本机无 shellcheck）。
- 实施完成后，请你在测试机上先贴：`cat /etc/os-release | head -3`、`dnf repolist --enabled`、`tail -30 ~/.local/state/eilNiri/{waybar,fuzzel,hypridle,copyq,playerctl,brightnessctl}-build.log`——用于确认 CRB 状态和每个构建的确切缺失项；然后删除 `.replicate_progress` 重跑 `restore`（或直接重跑，失败 stage 会自动重试）。
