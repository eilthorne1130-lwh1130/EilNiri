# RHEL-install.sh 补全方案（v1.9.26 → v1.10.0）

## 背景结论（已核实，无需从零写）

仓库里已有 **4264 行的 RHEL-install.sh（v1.9.26）**，骨架完整：发行版检测（rhel/fedora/centos 门控）、EPEL/CRB 启用、COPR、niri/awww/satty/hyprlock 源码编译、配置部署（`.bak-<时间戳>` 备份 + `is_privacy_risk` 隐私防线）、GDM 会话、rollback/status/restore-system/--dry-run 全都有。`configs/` 也已与本机同步（waybar/mako/niri/starship 与 `~/.config` 逐字节一致；`configs/.zshrc` 是脱敏版，不带本机的 miyu/kimi-code/opencode 行；copyq 剪贴板数据从未入库且部署侧有拦截）。

**真正的缺口有 5 个**（下面逐项修）：

---

## 1. COPR 修复（你遇到的 "enable 就报错" 根因已查明）

实测三个 COPR 项目的 chroot 支持情况：

| COPR 项目 | 实际 chroot | 现状 |
|---|---|---|
| `alebastr/sway-extras` | 仅 fedora-42~45/rawhide，**无 epel** | waybar/mako/fuzzel/grim/slurp/copyq/playerctl/brightnessctl 共 9 个包映射到它 → EL 上 enable 必报错 |
| `solopasha/hyprland` | 仅 fedora-rawhide，作者自警"勿用" | hyprlock/hypridle 映射到它 → 死的 |
| `yalter/niri` | fedora + **epel-10** ✓ | 唯一可用 |

修改（`RHEL-install.sh`）：
- `RHEL_COPR_PKG`（:274）只保留 `niri`/`xwayland-satellite` → `yalter/niri`，其余删除
- `ensure_rhel_coprs`（:793）：只 enable `yalter/niri`；EL 上**显式指定 chroot** `dnf copr enable yalter/niri epel-10-x86_64`（从 `VERSION_ID` 推导）；enable 前先 `curl -fsI https://copr.fedorainfracloud.org/coprs/<owner>/<proj>/repo/<chroot>/dnf.repo` 探测，404 或网络失败 → 干净跳过并提示，**彻底消除 Chroot not found 类报错**
- Fedora 分支继续跳过 COPR（官方源已覆盖全部组件，niri 已进 Fedora 官方仓库）
- 包降级链保持：官方仓库 → EPEL → COPR → 源码编译（`SOURCE_PKGS`/`build_hypr_stack` 已实现）→ MANUAL 清单
- `RHEL_FAIL_HINT`（:304）hyprlock/hypridle 的提示从 "try EPEL/Copr" 改为 "由脚本源码编译或 dnf install hyprlock（Fedora）"

## 2. zsh 美化补全（最大缺口）

现状：`:224` 注释引用的 `install_zsh_extras` **从未定义、从未调用**，也无 `chsh` → 部署的 oh-my-zsh 版 `.zshrc` 在 RHEL 上必然起不来（omz/starship/插件全缺）。另外 `load_app_universe`（:864）在非 arch 时把 `zsh` 从候选列表**过滤掉了**，导致 zsh 永远装不上。

修改：
- 移植 arch 的 `install_zsh_extras()`（arch-install.sh:1776）为 RHEL 版：oh-my-zsh + `zsh-autosuggestions` + `zsh-syntax-highlighting` 克隆进 `~/.oh-my-zsh/custom/plugins/`（GitHub 直连 + gitee 镜像回退）；starship → `dnf install`（Fedora 官方源有）→ get.starship.rs 官方脚本兜底 → 失败回退 `ZSH_THEME="agnoster"`；eza/bat/zoxide → dnf → EPEL → cargo/手动清单；batcat 符号链接兼容。适配点：`is_repo_pkg` 在 RHEL 上改用 `dnf -q list available` 语义；AUR 分支自然跳过；zoxide 失败提示改为 dnf 文案
- `load_app_universe` 取消对 RHEL 的 zsh 过滤（Fedora/EPEL 都有 zsh 包）
- 在 `stage_configs` 末尾接入（对齐 arch :2157/:2213/:2219 的位置）：`chsh -s "$(command -v zsh)" "$TARGET_USER"` + `install_zsh_extras`
- `configs/.zshrc` 已自带 `command -v` 守卫，无需改动

## 3. polkit 代理修复

现状：core 包组含 `polkit-gnome`（Fedora/EPEL 均无此包），脚本改写 spawn 路径到 `/usr/libexec` 却不装任何 agent → GUI 授权弹窗静默失效。

修改（已核实可用包）：
- core 组 `polkit-gnome` → 候选链 **`mate-polkit` → `polkit-kde`**（经 `RHEL_CANDIDATES` 解析；两者 Fedora+EPEL 均在维护；`lxpolkit` 已废弃并入 lxsession，不用）
- 移植 arch 的 `fix_polkit_agent()`（arch-install.sh:1945），扫描目录追加 **`/usr/lib64`**（Fedora 64 位路径），部署后把 `config.kdl` 的 polkit spawn 行改写到实际存在的 agent，找不到才警告
- 删除 `install_rhel` 里 "polkit-gnome not in dnf… skipping" 的误导日志（:1069 附近）

## 4. waybar 启动 bug

`stage_configs` :3278-3287 把 `spawn-at-startup "waybar"` 注释掉，理由是 "GDM/systemd 会启动 waybar"——但脚本并未创建任何 waybar unit，**结果状态栏直接消失**（arch 版在同样位置明确注释 "do NOT comment it out"）。删除该块，与 arch 对齐。

## 5. deb 脚本残留死代码清理

删除/修正：`apt_install_tolerant`、`install_niri_binary` 内 `check_clock_drift`/`set_debian_mirror` 调用（:1762/:1767，均未定义，若到达会触发 set -u）、`HYPR_BUILD_DEPS_DEB`（:2511）、诊断包里恒为 0 的 `UBUNTU_VER_NUM`、`ensure_pc_deps` 里 tail 不存在的 `apt-errors.log`（:1468）、:2292 缩进。
