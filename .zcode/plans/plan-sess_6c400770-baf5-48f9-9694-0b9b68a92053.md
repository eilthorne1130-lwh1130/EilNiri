## 方案：`update` 子命令（apt 升级 + 源码组件升级）+ restore 末尾询问

### 1. 版本探测（新增两个小函数，供版本对比用）
- `niri_latest_version()`：抽取 install_niri_binary 内已有的两段式获取逻辑（releases/latest 302 重定向优先、GitHub API 兜底），独立成函数；install_niri_binary 原逻辑保持不动（最小侵入）。
- `awww_latest_version()`：`git ls-remote --tags "$AWWW_REPO"` 取最高 `v*` tag（`sort -V`）；取不到（无 tag/网络）返回空。
- xwayland-satellite 无版本输出途径（`--version` 直接 panic，已实测）→ 菜单中标注“无版本信息，重装最新源码”，由用户决定。

### 2. 三个安装函数支持强制更新
`install_niri_binary` / `install_awww` / `install_xwayland_satellite` 的“已装即跳过”分支各加一个条件：`EILNIRI_FORCE_UPDATE=1` 时不走 SKIPPED 分支、直接走下载/编译路径（restore 流程不设该变量，行为完全不变）。DRY_RUN 分支在已装检查之后，force+dry-run 组合自动打印计划。

### 3. 新增 `do_update()` 子命令
流程（root，`init_logger/check_root/detect_distro/detect_target_user` 四件套 + `ensure_fzf` + `apply_cargo_mirror`）：
1. `apt-get update`，统计可升级数（`apt-get -s upgrade | grep -c '^Inst'`）
2. 版本对比：niri（本地 `niri --version` 取第二字段 vs latest tag）、awww（本地 `awww --version` vs Codeberg 最高 tag，取不到则显示 `-> latest main`）、xws（显示当前 `cargo install --list` 版本或“未知”）
3. **fzf_multi 菜单勾选**要更新的项（默认全选）：`apt`（N 个可升级）/ `niri x -> y（源码编译）` / `awww x -> y` / `xwayland-satellite -> latest`。**已是最新/无可升级的项不进菜单**；菜单为空则提示“全部已是最新”返回。无 fzf 时退化为编号多选（沿用 set_debian_mirror 的编号菜单模式）。
4. 执行（顺序固定 **niri → awww → xws**，满足 awww 低内存串行逻辑对 `BG_JOBS[0]` 是 niri 的假设）：设 `EILNIRI_FORCE_UPDATE=1` 依次调用对应 install 函数；niri/awww 走既有后台编译（`bg_build_start`），`./deb-install.sh status` 天然兼容
5. `stage_wait_builds` 等待收尾：加 `EILNIRI_NO_STAGE_MARK` 开关——设置时跳过 `stage_mark apps`（update 子命令绝不污染 restore 的断点文件；restore 不设该变量，行为不变）
6. 汇总输出（复用 INSTALLED_PKGS/SKIPPED_PKGS/MANUAL_ITEMS 打印）

### 4. restore 末尾询问 + main/usage
- `do_restore()` 在 `save_diag_bundle` 之后追加：`confirm "是否立即检查并升级软件包（apt 升级 + 源码组件重编译）？[Y/n] (default N, 20s)" "N" 20` → 是则调用 `do_update`（默认 N：首次装完都是最新的，给的是选项而非默认动作）
- `main()` 两处 case 与 `usage()` 加 `update`；README 命令一览表补一行

### 5. 不升 PROGRESS_VERSION
update 不调 stage_mark，restore 末尾询问是直调——不影响断点语义。

### 6. 测试（/tmp/eilniri-test/run_tests6.sh）
- force 开关：`EILNIRI_FORCE_UPDATE=1` + DRY_RUN 下三个函数不再 SKIPPED（断言 DRY_PKGS/日志）；不设时保持 SKIPPED（回归）
- `EILNIRI_NO_STAGE_MARK=1` 时 stage_wait_builds 不写 progress 文件（mock BG_JOBS 空/非空两分支）
- 版本对比辅助：niri_latest_version（mock curl）、awww_latest_version（mock git ls-remote）返回值
- 菜单构造：fzf_multi mock 返回选择，断言 apt/niri/awww/xws 选中项分别触发对应安装函数（mock 计数）；无可升级项时提示并返回
- main 分发 `update`、usage 含 update
- 回归：run_tests4/5、run_all 重跑
