## 复查结论

已核对三轮改动全部 diff、stage_configs 补丁链调用顺序、do_restore 挂接位置、set -u 变量初始化、heredoc 语法与三轮测试结果（76/76 通过，bash -n 干净）。发现 **1 处必修隐患**，其余确认无问题：

### 必修：wrapper 会话日志重定向缺失败保护（deb-install.sh 约 815 行）
现状：`mkdir -p ... || true` 之后**无条件** `exec &>> "$_slog/session.log"`。bash 非交互 shell 中 exec 重定向失败（state 目录不可写：磁盘满、只读 home、异常挂载）会**直接退出 wrapper** → niri 会话根本不会启动——诊断日志反而把会话搞挂，比黑屏更糟。
修法：`if mkdir -p ... && touch ...; then exec &>> ...; fi` —— 先验证可写，失败则放弃日志继续正常启动。

### 确认无问题项（复查记录）
1. `_vm_graphics_probe`：local 变量声明后立即赋值，`info_kv` 有 `:-fallback`，set -u 安全；三档分支（无 DRM / QXL / virtio）逻辑正确，非 VM 直接返回。
2. stage_configs 补丁链顺序正确：single_source(5390) → waybar 参考版(5393) → fcitx5(5397) → zsh(5401) → waybar JSON 校验(5404) → waypaper ExecStartPre(5441) → 壁纸(5448)；waybar 参考 config 是 waybar 自己的 JSON，与 niri config.kdl 的 spawn 行改写互不干扰。
3. do_restore 挂接：`_vm_graphics_probe` 在 detect_distro 后每次必跑；`_apply_wallpaper_if_awww` 在 stage_verify 后调用，时序上 awww 已尘埃落定。
4. wrapper 由 `repair_niri_blackscreen` 每次 restore 重新生成，`PROGRESS_VERSION` 保持 v44 即可（本轮关键逻辑都在 stage 门控之外，重跑即生效，无需强制全 stage 重装）。
5. 已知低危瑕疵（不改）：`deploy_zsh_config`/`install_zsh_extras` 在 DRY_RUN 块内调用，dry-run 报告不含 oh-my-zsh 条目——与既有 `_ensure_wallpaper` 等函数的模式一致，函数内 DRY 分支保留作防御。
6. save_diag_bundle 新增采集段全部带 `|| echo` 兜底，root 下运行无权限风险。
