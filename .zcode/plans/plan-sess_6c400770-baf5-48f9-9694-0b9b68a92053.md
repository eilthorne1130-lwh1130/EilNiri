## 修复方案（仅改 /home/eilthorne/EilNiri/deb-install.sh，config.kdl 模板不动以免影响 arch/RHEL 脚本）

### 1. 发行版识别（`detect_distro`，约 425-452 行）
- 判定条件放宽为：os-release 的 ID/ID_LIKE 含 debian/ubuntu 子串，**或** 存在 `/etc/debian_version`（所有 Debian 衍生包括 deepin/UOS/麒麟/Kali/MX 都有该文件，Ubuntu 也有）→ `DISTRO_FAMILY=debian`。两者皆无才报错。
- ID 为 ubuntu/mint/pop 时照旧解析 `VERSION_ID` 供发布版判断；其他衍生统一按 Debian 逻辑走（现有 `apt_available` 过滤已能兜住包名差异）。

### 2. waybar 双启动（幂等单实例化）
- 新增 `install_waybar_guard()`：生成 `/usr/local/bin/eilniri-waybar-start`（`pgrep -x waybar >/dev/null || exec waybar`），在部署后处理中把 config.kdl 的 `spawn-at-startup "waybar"` 改写为守卫脚本行并去重 —— 即使机器上存在第二个启动源，第二个实例也会自动退出。
- 新增清理步骤：`systemctl --user disable waybar.service`（Debian 包自带该 user unit，被启用时会随 graphical-session.target 拉起第二条栏）；移除 `~/.config/autostart/waybar*.desktop`。
- 修复 `_ensure_waybar_config()`（2318-2342）的逻辑反转 bug：现在正常配置也会被判为无效而误删 `ignored-sinks`，且会在 root 下启动真实 waybar 进程。改为纯 JSON 语法检查（jq/python3），仅在确认解析失败时才删该行。

### 3. fcitx 修复
- 新增 `configure_ime_env()`（对齐 arch 版 1629-1651 行的缺失部分）：写 `~/.config/environment.d/00-ime.conf` 并幂等追加 `/etc/environment`（GTK_IM_MODULE/QT_IM_MODULE/XMODIFIERS/SDL_IM_MODULE=fcitx）——目前 deb 版完全不写 IME 环境变量，systemd/XDG autostart 启动的应用拿不到变量，这是“高亮预编辑词消失”的主因之一。
- 不部署任何 fcitx5 主题/美化：保持现有 4060-4062 行跳过 fcitx5 目录的逻辑；rime-ice 词库照常。
- 预编辑兜底：为 `~/.config/fcitx5/conf/rime.conf` 幂等写入 `PreeditInApplication=False`（实现时先在线核实 fcitx5-rime 键名，核实不到则跳过此项，以环境变量修复为主），让组词高亮显示在候选窗而非应用内，绕开应用端 preedit 缺陷。
- fcitx5 单实例：若存在 `/etc/xdg/autostart/org.fcitx.Fcitx5.desktop`，为目标用户写 `Hidden=true` 的用户级屏蔽文件，避免与 niri `spawn-at-startup "fcitx5"` 双实例互抢。

### 4. 显示参数注入（`stage_hardware_adapt` 4397-4471 + wrapper 709-761）
- 修 bug：连接器名提取 `card[0-9]-` 只支持单位数卡号 → 改 `card[0-9]+-`（两处）。
- 注入逻辑重写：枚举**全部** connected 连接器，为每个生成干净的 output 块（第一个加 `focus-at-startup`；不再写死 mode/scale/position —— 模板机遗留的 `DVI-D-1`/`1920x1080@60`/`scale 1.2`/`position` 全部清除，niri 自动选首选模式）；未连接的连接器块用 `/-output` 注释。多显示器（笔记本 eDP-1 + 外接）不再选错。
- 写完执行 `niri validate`，失败自动回滚备份并告警（现在只 warn 不回滚）；登录期 wrapper 同步升级为相同“全连接器重写”逻辑。

### 5. 默认壁纸（`_ensure_wallpaper` 2205-2316）
- 根因：函数开头 awww 二进制不存在就直接 return（awww 是 cargo 后台源码编译，任何一步失败就没有壁纸），导致仓库壁纸不复制、waypaper/hyprlock 路径仍是未展开的 `$HOME` 字面量 → 全部失效。
- 重构为两段：**壁纸文件与配置修正无条件执行**（复制 `QQ图片20260713144149.jpeg` → `~/.local/share/backgrounds/wallpaper.jpg`；waypaper config.ini 的 wallpaper/folder 写展开后的绝对路径；hyprlock.conf 的 `background.path` 收紧为仅改 background 块内的 path 行）；awww 相关（状态文件、daemon、`awww img`）仅在 awww 存在时执行；awww 缺失时降级为告警 + MANUAL_ITEMS 提示，不再整体跳过。登录后 `waypaper.service --restore` 即可恢复仓库那张壁纸。

### 验收
- `bash -n` 语法检查；对 `detect_distro`、注入重写、`_ensure_wallpaper` 做函数级模拟测试（伪造 os-release / 临时 HOME + 样例 config.kdl）。
- 对照你的验收标准逐项自查：waybar 单实例、fcitx 环境变量三处一致（niri 块/environment.d//etc/environment）、显示参数注入正确可回滚、任意 Debian 衍生可通过识别、默认壁纸不依赖 awww 编译成功。
