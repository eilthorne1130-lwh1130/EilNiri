# laptop-need-install.sh 修复计划（v1.1.0：修复坍缩故障 + 台式机支持 + 三脚本适配）

## 根因分析
1. **"只剩一个小药丸"**：`restart_waybar` 的重启方式有致命缺陷——pkill 后用「白名单 4 个环境变量（WAYLAND_DISPLAY/XDG_RUNTIME_DIR/DISPLAY/DBUS）+ runuser + setsid」重建进程。丢失了 `NIRI_SOCKET` 等关键会话变量 → `niri/workspaces`、`niri/window` 模块无法连接 niri IPC 而消失；且 runuser+`&` 拉起的进程可能随会话回收被杀。**配置文件本身没有损坏**（JSON 注入经过原子写与内存验证，`.bak-bat-*` 备份也在），坏的只是被错误环境重启的 waybar 进程。
2. **台式机没加电量模块**：`detect_battery` 探测无电池 → confirm 默认 N → 15s 超时自动选"不添加"。

已核实的技术事实：SIGUSR2 热重载有已知不完全重载 bug（waybar #3986），不能可靠加载新模块，弃用；niri IPC 支持 `niri msg action spawn -- <cmd>`（官方 wiki / Action::Spawn），**由 niri 拉起的进程继承 niri 的完整环境（含 NIRI_SOCKET），与 spawn-at-startup 完全同源**——这是重启 waybar 的正确方式。

## 修改内容（仍只改 laptop-need-install.sh）

### A. 重写 restart_waybar（修坍缩）
- waybar 未运行 → 仅提示"下次登录生效"，不做任何事。
- **首选**：以目标用户执行 `niri msg action spawn -- /usr/local/bin/eilniri-waybar-start`（守卫存在时）或 `spawn -- waybar`。root 模式下仅为这一次 msg 调用从运行中 waybar 的 `/proc/<pid>/environ` 借取 `NIRI_SOCKET`+`XDG_RUNTIME_DIR`（借出的新 waybar 用的是 niri 自己的完整环境，不再有白名单问题）。
- **次选**（niri msg 缺失/失败）：python3 全环境重启——读取整个 `/proc/<pid>/environ` 与 `cmdline`，setsid 后 execve 原命令原参数（本脚本已硬依赖 python3，引号安全、环境完整）。
- **兜底**：警告并打印手动恢复命令（`pkill -x waybar` 后重新登录，或 `niri msg action spawn -- waybar`），绝不静默留下无栏桌面。
- 重启后 `sleep 2` + `pgrep -x waybar` 验证：成功 → success；失败 → warn + 手动提示。dry-run 只打印命令。

### B. 台式机支持（修"也要有电量模块"）
- 电池探测降级为纯信息展示（info_kv），confirm 默认值**恒为 Y**（15s 超时自动确认）。无电池台式机写入模块后 waybar 自动隐藏该模块（仓库 deb 脚本注释已确认此行为无害）。

### C. 三主脚本产物适配（承接上轮已核对结论）
- JSON 注入前剥离整行 `/* ... */` JSONC 注释（防御 arch/RHEL hwadapt 对 ignored-sinks 的注释产物）；剥离后仍解析失败 → 中止不动文件。
- CSS 兜底：若 `#battery.charging` 缺失，随基础样式追加参考版三条状态色（style.css:198-209 逐字复刻）；若 `@keyframes blink` 缺失，追加 keyframes（style.css:335-345 逐字复刻）。各自独立幂等守卫。
- 头部注释/usage 写明适配矩阵：arch/RHEL 快照参考版、deb ≥0.10 内嵌参考版、deb 0.9.x 平铺版、deb 已加过 battery（interval 30 → 重跑刷新为 10）。
- SCRIPT_VERSION → 1.1.0。

## 已损坏测试机的恢复（写给用户，脚本不含此逻辑）
配置文件完好，无需回滚：**重新登录**（niri spawn-at-startup 会以正确环境拉起 waybar，电量模块直接出现），或执行 `pkill -x waybar && niri msg action spawn -- waybar`。需要回滚配置时用 `.bak-bat-*` 备份。
