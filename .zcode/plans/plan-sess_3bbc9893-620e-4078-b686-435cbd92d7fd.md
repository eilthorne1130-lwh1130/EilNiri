# fcitx5-qt / marisa / leveldb 修复（v1.11.16）——按测试机诊断报告实施

诊断报告已给出三个问题的精确根因与修法，全部采纳：

## 修改项

### 1. fcitx5-qt：注入 find_package(Qt6GuiPrivate REQUIRED)
- 根因：qt6/platforminputcontext 链接 `Qt6::GuiPrivate`，但 fcitx5-qt 5.1.10 的 CMakeLists 从未 find_package 私有组件（qt6-qtbase-private-devel 已装、Qt6GuiPrivateConfig.cmake 存在，只是没人去 find）→ Generate 阶段 "Qt6::GuiPrivate was not found"
- 修法：clone 后检测 platforminputcontext 引用了 GuiPrivate 且顶层未声明时，向 `qt6/CMakeLists.txt` 开头（add_subdirectory 之前）注入 `find_package(Qt6GuiPrivate REQUIRED)`（Qt6GuiPrivateConfig.cmake 由已装的 qt6-qtbase-private-devel 提供）

### 2. marisa：clone 目录名修复（脚本逻辑 bug）
- 根因：`install_rime_build_libs` 克隆 marisa 到 `$work/marisa-trie`，但 `build_source_project` 期望 `$work/marisa`（按 pkg 名拼路径）→ 找不到构建文件 → "empty or corrupt clone" → return 1 → rime 链第三步必挂
- 修法：克隆目标改为 `$work/marisa`（与 leveldb/opencc 的命名一致）

### 3. leveldb：消除每轮重编
- 根因：leveldb 源码安装不产生 .pc，`pkg-config --exists leveldb` 永假 → 每轮重跑都重编（日志已确认第二个 run 又是 [rime 0a]）
- 修法：检测条件追加头文件存在性——`pkg-config --exists leveldb || [ -f /usr/include/leveldb/db.h ]` 即视为已装（leveldb 的 cmake install 会装 /usr/include/leveldb/db.h 与 /usr/lib64/libleveldb.so）

### 4. 版本 1.11.15 → 1.11.16
