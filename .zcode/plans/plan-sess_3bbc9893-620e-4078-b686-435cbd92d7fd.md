# fcitx5 preedit 修复计划

## 根因（诊断报告确认）
`PreeditInApplication=False` 是已废弃的无效键（fcitx5-rime 5.1.16 已移除，fcitx5 静默忽略未知键），从未生效。正确开关是 fcitx5 核心的 `~/.config/fcitx5/config` → `[Behavior] PreeditEnabledByDefault=False`（组词高亮显示在候选窗，绕开应用端 preedit 渲染空白）。仓库中无效键的两处源头：`configs/.config/fcitx5/conf/rime.conf`（提交 3831d46）与 `deb-install.sh:3469-3481` 写入逻辑（提交 e2876e0）。arch/RHEL 脚本本身无此写入。

## 一、configs 快照
1. **删除** `configs/.config/fcitx5/conf/rime.conf`（唯一内容即无效键+注释）
2. `configs/.config/fcitx5/config`：`PreeditEnabledByDefault=True` → `False`，注释同步改为说明"关闭应用内 preedit，组词在候选窗显示"
3. `configs/.config/fcitx5/conf/classicui.conf`：`Theme=default-rounded` → `Theme=default`（用户选择；DarkTheme=default-dark 已是系统自带，不动）
4. 删除空目录 `configs/.config/fcitx5/themes/`

## 二、本机 live（用户已确认同步改）
- `~/.config/fcitx5/config` 的 `PreeditEnabledByDefault=True` → `False`，与快照保持一致，避免下次同步漂移（fcitx5 会自动重载配置）

## 三、deb-install.sh
1. **替换** L3469-3481 的坏写入块：改为 ① 幂等 `sed` 已部署的 `~/.config/fcitx5/config` 中 `PreeditEnabledByDefault` 为 `False`（覆盖已有配置不被 heredoc 覆盖的机器）；② 清理历史残留——从已存在的 `conf/rime.conf` 中删除 `PreeditInApplication` 行及配套 eilNiri 注释行，文件清空则删除；③ 日志文案更新
2. heredoc 内 `PreeditEnabledByDefault=True` → `False`（L3553 附近，注释同步）
3. stage_configs 的 `.local/share` 部署循环同样 skip `fcitx5|fcitx`（与 L5717-5718 对 `.config` 的 skip 对称，维持"deb 版不部署 fcitx5 美化"的既有意图）
4. `SCRIPT_VERSION` → 1.9.35

## 四、arch-install.sh
1. IME 环境变量 heredoc（~L2181）修正：`GTK_IM_MODULE/QT_IM_MODULE/SDL_IM_MODULE=fcitx`、`XMODIFIERS=@im=fcitx`、`GLFW_IM_MODULE=ibus`——与本机 niri environment 块、deb/RHEL、测试机实证一致（现在写的 `fcitx5` 值是错的）；文件名 `ime.conf` → `00-ime.conf` 并参照 RHEL 版清理旧文件（实施时对照 RHEL L3553-3556 的清理写法）
2. `SCRIPT_VERSION` → 2.0.1
3. 快照修复后部署链路自动正确：测试机重跑 `sudo ./arch-install.sh restore`，deploy_one 整目录替换 fcitx5 → 坏 rime.conf 消失、拿到 False 配置，无需额外逻辑
