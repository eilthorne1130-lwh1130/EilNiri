# RHEL-install.sh EL10 第三轮修复计划（v1.11.3）

## 诊断结论（本轮截图）
1. **power-profiles-daemon "没有任何匹配"是 EL10 的既定事实**：RHEL 10 系用 **tuned-ppd**（PPD 兼容守护，提供相同 D-Bus API，`Requires=tuned.service`）替代了独立的 power-profiles-daemon 包。不是仓库坏了，是包真的不存在。
2. **copyq 打地鼠第三棒：ECM**——`src/CMakeLists.txt:22` 无条件 `include(notifications.cmake)`，其内 `find_package(ECM REQUIRED)` + `find_package(KF6 Notifications/StatusNotifierItem REQUIRED)`（受 `WITH_NATIVE_NOTIFICATIONS` 选项控制，默认 ON）。已核实全部可选链：`WITH_NATIVE_NOTIFICATIONS`→ECM+KF6、`WITH_AUDIO`→miniaudio、`WITH_QCA_ENCRYPTION`→qca+qtkeychain（上一轮已处理）。EL10 无 KF6 栈/miniaudio，需逐项降级。qwt/kf6-\* 是 Fedora spec 特有，上游非必需，不加。
3. fcitx5 源码编译的基建全部现成（`build_source_project`、`git_clone_gh`、`install_fcitx5_rime_source` 及其 fcitx5-devel 前置检查），缺的只是 fcitx5 本体链。已核实 fcitx5 5.1.23 的完整硬依赖（ECM、XCB+XCBImdkit、XKBCommon、IsoCodes、XKeyboardConfig、nlohmann_json、Wayland≥1.22+protocols、cairo/pango/gdk-pixbuf/librsvg/gio、enchant-2、ZLIB、libuuid、systemd）。

## 修改项

### A. power-profiles-daemon → tuned-ppd（EL10 事实修正）
1. `RHEL_CANDIDATES` 加 `power-profiles-daemon → power-profiles-daemon / tuned-ppd`（Fedora 命中前者，EL10 解析到后者）
2. `stage_services`：provider 安装前经 `resolve_rhel_package` 解析；解析为 `tuned-ppd` 时 enable 的 unit 替换为 `tuned-ppd.service`
3. `stage_disable_system`：mask `tuned.service` 前检测 `pkg_installed tuned-ppd`，命中则跳过（tuned-ppd 依赖 tuned，mask 会断链）——现有 DISABLE_SYS 条目不动，逻辑上加白名单
4. 已有的 tuned 冲突询问分支保留（Fedora/EL9 场景仍有效）

### B. copyq 源码构建一次到位（终结打地鼠）
1. `SRC_DEPS_COPYQ` += `extra-cmake-modules qt6-qtbase-private-devel libXfixes-devel miniaudio-devel`
2. `CMAKE_EXTRA_ARGS` 逻辑扩展：
   - qca/qtkeychain 缺任一 → `-DWITH_QCA_ENCRYPTION=OFF`（已有）
   - `miniaudio-devel` 缺 → `-DWITH_AUDIO=OFF`（损失提示音）
   - `kf6-knotifications-devel` 缺（EL10 无 KF6）→ `-DWITH_NATIVE_NOTIFICATIONS=OFF`（损失系统原生通知集成；托盘回退 Qt 自绘，剪贴板核心不受影响）

### C. COPR 可用性检查强化（用户要求）
`ensure_rhel_coprs` 启用成功后加包可见性探测：`dnf -q --disablerepo='*' --enablerepo='*yalter*niri*' list available niri`，失败 → warn + MANUAL_ITEMS（chroot 未构建/元数据未同步；后续 cargo 源码编译兜底自动接管）

### D. fcitx5 源码编译兜底（用户核心诉求）
1. 新增 `SRC_DEPS_Fcitx5`（tolerant 安装）：`extra-cmake-modules glib2-devel gdk-pixbuf2-devel iso-codes-devel xkeyboard-config-devel nlohmann-json-devel expat-devel libxkbfile-devel xcb-imdkit-devel plasma-wayland-protocols-devel systemd-devel dbus-devel`
2. 新增 `install_fcitx5_source()`（仅 EL 非 Fedora，幂等）：
   - fcitx5 core（`fcitx5/fcitx5` tag 5.1.23）→ `CMAKE_EXTRA_ARGS=(-DENABLE_ENCHANT=OFF -DENABLE_EMOJI=OFF -DENABLE_TEST=OFF -DENABLE_TESTING_ADDONS=OFF -DENABLE_DOC=OFF)` 精简依赖面
   - fcitx5-gtk → fcitx5-qt（build_source_project 自动判定构建系统）
   - fcitx5-rime → 复用既有 `install_fcitx5_rime_source`（此时 fcitx5 头文件已就位，其 bail-out 检查通过；librime 源码编译已支持）
   - 每步失败 → MANUAL_ITEMS（含日志），不中断后续步骤
3. 分发层 `install_rhel` 的 `^fcitx5` 短路改造：
   - `fcitx5-configtool` → SKIPPED（依赖 KF6，EL10 不可得；配置已随脚本部署无需 configtool）
   - `fcitx5/fcitx5-gtk/fcitx5-qt` → `install_fcitx5_source`
   - `fcitx5-rime` → SKIPPED（由 install_rime_ice 链统一处理）
4. 风险注释：wayland-protocols ≥1.46（EL10 实际版本待实测）、xcb-imdkit/plasma-wayland-protocols 在 EPEL10 的可得性——tolerant + 失败日志已真实化
