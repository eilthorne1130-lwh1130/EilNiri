# hyprlock/hypridle 修复计划（v1.11.12）——移植 deb 版 hypr 构建机制

## 根因（代码级调查确认）
1. **hyprland-protocols 是 meson-only 项目**（无 CMakeLists.txt），RHEL 版 `build_hypr_stack` 用 cmake 构建它 → 第一步必然失败 → 整栈 `return 1` → "hypr C++ build stack could not be built"
2. **全部组件克隆 master 无 pin**（deb 版有 7 个 HYPR_PIN_*）：hyprutils master 需 C++26 > EL10 g++14 的 C++23
3. `HYPR_BUILD_DEPS_RHEL` 缺 meson；无 C++23 工具链实测；install 后无 ldconfig；克隆输出进 /dev/null（失败无痕）；单一 hypr-stack.log 无组件隔离；hyprgraphics 未按目标裁剪（仅 hyprlock 需要）

## 修改项（RHEL-install.sh，1.11.11 → 1.11.12）

### A. pin 常量 + helper（照搬 deb 版 tag）
`HYPR_PIN_SCANNER=v0.4.4 / HYPR_PIN_UTILS=v0.8.4 / HYPR_PIN_LANG=v0.6.3 / HYPR_PIN_GRAPHICS=v0.1.3 / HYPR_PIN_PROTOCOLS=v0.6.4 / HYPR_PIN_IDLE=v0.1.7 / HYPR_PIN_LOCK=v0.8.2` + `hypr_git_ref()`（组件名→tag；无 pin 的组件名直接失败——与 deb 一致的策略）

### B. build_hypr_stack 重写（对齐 deb，EL 简化）
- 每组件独立日志 `hypr-stack-<n>.log` + 主日志头行（`=== name ref=tag cxx=g++ ===`）
- 克隆带 pin；克隆失败写组件日志 + 具名 warn
- **构建系统探测**：有 CMakeLists.txt→cmake；仅有 meson.build→meson 分支（hyprland-protocols 走此路；缺 meson 现场 `pm_install meson ninja-build`）
- cmake 参数 += `-DCMAKE_CXX_STANDARD=23 -DCMAKE_CXX_STANDARD_REQUIRED=ON`；install 后 `ldconfig`
- C++23 工具链实测：候选 g++/clang++，`-std=c++23 -fsyntax-only` 探针，成功 export CXX/CC，全失败 → MANUAL + return 1
- 顺序（对齐 deb）：pugixml 兜底（pkg-config 缺→源码 v1.14）→ hyprwayland-scanner → hyprutils → hyprlang → hyprland-protocols → hyprgraphics（仅 _want=hyprlock）→ sdbus-c++ 兜底（pkg-config 缺→源码 v2.1.0，tests/examples/codegen 全 OFF）→ 整体复核 + `hypr-stack.ok` 标记
- 失败：组件日志 tail -40 追加主日志 + 具名 warn（含组件日志路径）

### C. install_hypr_source 对齐
- hyprlock/hypridle 克隆带 pin（hypr_git_ref）
- `build_hypr_stack "$pkg"`（目标裁剪）
- cmake += CXX_STANDARD=23；失败文案修正为列 hyprland-protocols/scanner

### D. 杂项
- `HYPR_BUILD_DEPS_RHEL` += meson，删无效的 libpam-devel
- 删 RHEL_FAIL_HINT 中永不触发的 hypr 死代码条目
- 版本 1.11.11 → 1.11.12
