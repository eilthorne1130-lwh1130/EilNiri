# fcitx5 配套模块修复计划（v1.11.8）

## 诊断结论（回答你的三个问题）

**1. fcitx5 core 已经编译成功**——json-c/fmt/libuv 修复生效，它已不在失败列表。现在失败的是配套模块，各有明确根因。

**2. 为什么配套模块一直失败**（三类根因）：
- `fcitx5-gtk`：fcitx5-gtk **默认构建 GTK2+GTK3+GTK4 三个 IM 模块**，GTK2 模块的 `pkg_check_modules(gtk+-2.0)` 失败（EL10 缺 gtk2-devel）。已核实上游提供 `ENABLE_GTK2_IM_MODULE` 选项——GTK2 IM 模块对现代 Wayland 桌面毫无必要，直接关闭。
- `fcitx5-qt`：**编译期**报 `fcitx-utils/standardpaths.h` 找不到——fcitx5-qt 用的是未 pin 的 master，其 API/头文件依赖已超前于刚装的 fcitx5 5.1.10 core。**仓库 tag 查证结果**：fcitx5-qt 5.1.9（2025-01-22）与 fcitx5 core 5.1.10 同期，API 配套（fcitx 生态的 qt 模块版本与 core 同代发布）。
- `fcitx5-rime` + `rime-ice`（连锁）：同样未 pin——fcitx5-rime master / librime master 与 core 5.1.10 的配套性无保证。已核实 tag：**fcitx5-rime 5.1.10（2025-01-22）与 core 同期；librime 同期稳定版为 1.16.1**（最新 1.17.0，rime C API 虽稳但选同期更保守）。

**3. 关联包全景**：fcitx5-gtk（GTK3/4 输入法模块）、fcitx5-qt（Qt6 输入法模块）、fcitx5-rime + librime（rime 引擎）、rime-ice（词典，随引擎成功自动部署）、fcitx5-configtool（维持 SKIPPED，KF6）。另：hyprlock/hypridle 的 hypr C++ stack 失败与 fcitx5 无关，本轮不动（已记录，次优先）。

## 修改项（全部在 RHEL-install.sh，v1.11.7 → 1.11.8）

1. **fcitx5-gtk**：构建时 `CMAKE_EXTRA_ARGS=(-DENABLE_GTK2_IM_MODULE=OFF)`（GTK3/4 模块保留）
2. **新增三个配套 tag 常量**并接入 clone 调用（git_clone_gh 第三参数）：
   - `FCITX5_QT_SRC_TAG="5.1.9"`（fcitx5-qt）
   - `FCITX5_RIME_SRC_TAG="5.1.10"`（fcitx5-rime）
   - `LIBRIME_SRC_TAG="1.16.1"`（librime）
   注释写明"与 fcitx5 core 5.1.10 同期发布、API 配套"的 pin 原则
3. rime-ice 无需改动（fcitx5-rime 成功后自动部署，链已有）
4. 版本号 bump

## 验证
- `bash -n`；grep 核对三处 clone 均带 tag
- 测试机重跑预期：fcitx5-gtk 跳过 GTK2 后配置通过 → fcitx5-qt 用 5.1.9 编译通过（头文件 API 与 core 5.1.10 匹配）→ fcitx5-rime 5.1.10 + librime 1.16.1 构建成功 → rime-ice 词典自动部署 → 中文输入可用
