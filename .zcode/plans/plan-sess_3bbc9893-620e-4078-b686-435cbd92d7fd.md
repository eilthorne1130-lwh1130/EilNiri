# fcitx5 修复方案（v1.11.6）——降 pin tag，从根上绕开协议库依赖

## 回应你的两点
1. **Fedora 43 清华镜像只是佐证**：EL10 的 wayland-protocols 就是 1.45（Rocky/Alma 10 与 Fedora 43 同期），引用它是为证明"系统包版本不够 1.46"，不是要用 Fedora 的包。
2. **放弃 CN 网络优化 → 方案反而更简单**：与其修 wayland-protocols 的获取路径，不如直接降 fcitx5 的 pin tag。已逐 tag 核实上游 CMakeLists：
   - 5.1.21 / 5.1.22：仍要求 WaylandProtocols ≥1.46（排除）
   - **5.1.10：`find_package(WaylandProtocols REQUIRED)` 无版本要求 → EL10 的 1.45 直接满足；且完全没有 PlasmaWaylandProtocols 依赖** → 两个协议库源码兜底步骤整体不再需要
   - XCBImdkit 1.0.3 要求不变（第 0 步源码编译的 master 满足）；yoga submodule 由 `git_clone_gh` 内置的 `_git_clone_submodules` 自动拉取（直连 GitHub，你的网络无压力）

## 修改项（RHEL-install.sh）

1. **`FCITX5_SRC_TAG` 5.1.23 → 5.1.10**，注释更新选择理由（EL10 系统库直接满足、与参考机 5.1.23 的差异仅为新协议支持，对 rime 输入无实质影响——引擎由 fcitx5-rime 提供、词库是 rime-ice）
2. **删除 `install_fcitx5_protocol_libs()` 函数及其调用**、`WAYLAND_PROTOCOLS_REPO`/`PLASMA_WAYLAND_PROTOCOLS_REPO` 常量、`SRC_DEPS_Fcitx5` 中的 `plasma-wayland-protocols-devel`——不再需要
3. **yoga 检查简化**：删掉上轮加的代理重写重试块（CN 优化），改为 clone 后检查 `third_party/yoga` 目录非空，缺失则显式 `git submodule update --init`，仍失败给明确 MANUAL 提示（fail-fast，替代 cmake 的隐晦报错）
4. 版本 1.11.5 → 1.11.6

## 验证
- `bash -n`；grep 确认协议库相关代码清除干净、tag 生效
- 测试机重跑预期：wayland-protocols/plasma 两步消失，fcitx5 core 直接用系统 1.45 的 wayland-protocols 配置通过，链推进到编译阶段；若 yoga 缺失会得到明确的 MANUAL 提示而非隐晦 cmake 报错
