# hyprlock 修复计划（v1.11.13）——hyprgraphics 的 libspng 源码兜底

## 诊断（当前失败点分析）

v1.11.12 的构建顺序已与 deb-install.sh 完全一致（pugixml → scanner → utils → lang → protocols → graphics[仅 hyprlock] → 复核），meson-only 的 hyprland-protocols 也已走 meson 分支。剩余失败嫌疑逐组件排查后锁定：

- **hyprgraphics v0.1.3 的 `spng`（libspng）是 REQUIRED 且没有任何 CMake 选项可以关闭**（已核对上游 CMakeLists：`pkg_check_modules(deps REQUIRED ... pixman-1 cairo hyprutils libjpeg libwebp libmagic spng)`）——EL10 没有 libspng 包，hyprlock 目标（需要 hyprgraphics）必然在此失败。其余组件依赖（pugixml/sdbus-c++ 兜底、scanner/utils/lang/protocols 的 pin 构建）在 v1.11.12 已覆盖
- 失败组件的精确名字在你机器的 `hypr-stack.log` / `hypr-stack-<组件名>.log` 里（v1.11.12 已实现组件级日志）；本轮修复后若仍失败，MANUAL 与日志会给出组件名 + 尾部 40 行

## 修改项（RHEL-install.sh，1.11.12 → 1.11.13）

1. **新增 libspng 源码兜底**（build_hypr_stack 内、hyprgraphics 构建前，条件触发）：`pkg-config --exists spng` 缺失时从 `randy408/libspng` 源码编译（单文件 C 库，唯一依赖 zlib 已有），装到 /usr 提供 spng.pc；失败 → MANUAL（点名 + 日志路径）不中断
2. 依赖清单补注释说明 libspng 的来历（EL 无包）
3. 版本 1.11.12 → 1.11.13
