# RHEL-install.sh 第四轮修复计划（v1.11.4）

## 诊断结论
1. **`service:power-profiles-daemon.service` 失败的根因是 unit 替换的位置 bug**：替换逻辑写在"安装 provider"的 if 块内部。上一轮 restore 已把 tuned-ppd 装上，本轮重跑时 `pkg_installed tuned-ppd` 为真 → 跳过整个安装块（含替换）→ enable 又用回不存在的 `power-profiles-daemon.service` → 失败。**替换必须在安装块之外、每次循环都执行**。
2. **fcitx5 三次重复报 XCBImdkit 缺失**：① EPEL 10 拿不到 xcb-imdkit 包（Rocky 10 中文输入法教程证实需手动编译；无 fcitx5 COPR epel-10，已查证）——把 **xcb-imdkit 源码编译**加进 fcitx5 链（第 0 步，fcitx 官方小库，依赖的 xcb-util 系列 -devel 已在通用清单）；② 分发层 fcitx5/fcitx5-gtk/fcitx5-qt 三个条目各调一次整链，core 失败后重复 clone+build 三次、记录三条相同 MANUAL。
3. rime-ice 跳过行为正确（core 失败时无引擎）。

## 修改项

### A. unit 替换移出安装块（bug 修复）
- `stage_services`：`tuned-ppd` 的 unit 替换移到 resolve 之后、安装块之前（循环级无条件判断），已装场景也生效
- 防御：enable `tuned-ppd.service` 前若 `tuned` 处于 masked 则先 `systemctl unmask tuned`

### B. xcb-imdkit 源码编译进链（fcitx5 第 0 步）
- 新增 `XCB_IMDKIT_REPO`；`install_fcitx5_source` 在 core 之前检测 `pkg-config xcb-imdkit` / cmake config，缺失则 clone `fcitx/xcb-imdkit`（master）→ build_source_project 编译安装
- 幂等：检测已装则跳过

### C. 分发层去重（终结三次重复）
- `install_rhel` 的 fcitx5 case 改为：仅 `fcitx5` 本体调用 `install_fcitx5_source`（整链一次）；`fcitx5-gtk/fcitx5-qt/fcitx5-rime` 记 SKIPPED「由 fcitx5 源码链统一编译」；`fcitx5-configtool` 维持 SKIPPED（KF6）

### D. COPR 检查补全
- 已查证无 fcitx5 COPR epel-10（写进注释固化）；`ensure_rhel_coprs` 的可见性探测从只查 `niri` 扩展为同时查 `xwayland-satellite`
- `service:` 失败条目附带原因（unit 不存在时注明），不再只给裸名字

### E. 版本 1.11.3 → 1.11.4
