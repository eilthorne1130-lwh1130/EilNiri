# RHEL-install.sh 第五轮修复计划（v1.11.5）

## 回答你的两个问题（先说结论）
1. **COPR 没有启用失败**——它工作正常且探测逻辑正确。实测抓取 COPR 页面确认：`yalter/niri` 这个 COPR **只构建 niri 一个包**（26.04-1），从来没有 xwayland-satellite。所以 niri 从 COPR 正常可查，xwayland-satellite 查不到 → 走 cargo 源码兜底，符合预期。但脚本的 `RHEL_COPR_PKG` 表里写着 `[xwayland-satellite]=yalter/niri` 是**错误映射**（会让安装链多走一次注定失败的 COPR 重试），本轮修正。
2. **fcitx5 编译不是没生效，而是链在正常推进**——xcb-imdkit 已编过（日志无报错），本轮卡在 core 的 cmake：缺 `libxkbcommon-x11-devel`（清单漏了）。而且我已把**后面三个连环坑全部查证清楚**，本轮一次修完，不再打地鼠：
   - `wayland-protocols`：EL10 是 1.45，fcitx5 5.1.23 要求 **≥1.46** → 必须源码装新版
   - `plasma-wayland-protocols`：仅 EPEL 10.2+ 有（1.20+，满足要求），但你的系统是 10.0/10.1（dav1d el10_2 不可见佐证）→ 需要源码兜底
   - `third_party/yoga` 是 git submodule（facebook/yoga），`--depth 1` clone 不含它，cmake 默认需要

## 修改项

### A. fcitx5 链补全（一次到位）
1. `SRC_DEPS_Fcitx5` += `libxkbcommon-x11-devel`（本次缺失的 XKBCommon X11 组件）
2. **新增协议库源码兜底**（core 之前、条件触发、装到 `/usr/local` 不碰系统包）：
   - `wayland-protocols`：系统版本 <1.46 时，从 `gitlab.freedesktop.org/wayland/wayland-protocols` clone（master）→ meson 安装；gitlab.fd.o 直连不稳，失败记 MANUAL 并提示手动安装（纯数据 noarch，`meson setup+install` 秒级）
   - `plasma-wayland-protocols`：不可得或 <1.20 时，从 GitHub 官方 KDE 镜像 `KDE/plasma-wayland-protocols` clone（git_clone_gh 带 CN 代理）→ cmake 安装
   - 新增 `_ver_lt` 版本比较 helper（sort -V 实现）
3. **yoga submodule 补齐**：fcitx5 clone 成功后 `git submodule update --init --depth 1`；CN 网络失败时把 submodule URL 重写为 GH 代理前缀重试

### B. COPR 映射修正
- `RHEL_COPR_PKG` 删除 `[xwayland-satellite]=yalter/niri`（该 COPR 只构建 niri，已实测固化结论）；安装分发里 xwayland-satellite 不再走注定失败的 COPR 分支，直接 pm_install → EPEL → cargo 兜底
- `ensure_rhel_coprs` 的探测只查 niri（消除每轮必现的 xwayland MANUAL 警告噪音），注释写明 xwayland-satellite 不在该 COPR 中
